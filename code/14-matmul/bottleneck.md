# 14-matmul 四版瓶颈分析

> 硬件：RTX 4070 Ti Super（Ada，CC 8.9）
> FP32 峰值 44.1 TFLOPS，DRAM 带宽 672 GB/s，ridge point = 65.6 FLOP/byte
> 数据：N = 4096，2026-11-16 晚同一会话采集（ncu 在管理员终端）

| 版本 | min_ms | GFLOPS | AI | 落区 | 天花板 | 完成度 |
|---|---|---|---|---|---|---|
| naive | 60.63 | 2,266 | 14.7 | memory | 9,878 | 23% |
| tiled | 47.05 | 2,921 | 15.2 | memory | 10,181 | 29% |
| reg 4×4 | 10.84 | 12,677 | 31.6 | memory | 21,229 | 60% |
| reg 8×8 | 6.09 | 22,570 | 115.5 | **compute** | 44,100 | 51% |

---

## 1. naive —— 一个线程算一个输出

### 结论

naive 在 N=4096 上跑 60.63 ms，合 2,266 GFLOPS，是 FP32 峰值的 5.1%。
AI = 14.7，远低于 ridge point 65.6，落在 memory-bound 区。
对应带宽天花板 9,878 GFLOPS，实际达到 `2,266 ÷ 9,878 = 23%`。

### AI 为什么这么低

naive 没有 shared memory，每一个输出都要从 global 读取 N 次 A 和 N 次 B，
每做一次 FMA 就要发两条 global load。

### 复用率怎么计算

每个 block 读 `32*4096*4 + 4096*32*4 = 1 MB`，
一共 `4096/32 * (4096/32) = 16,384` 个 block，
无 L2 时总量 `16,384 MB = 16 GB`。
实测 9.35 GB，复用率 `16 / 9.35 = 1.71` 倍。

四版里最低——L2 几乎没帮上忙，省下的只是 block 行优先调度带来的那一小部分重复读。

### 天花板怎么取

`672 GB/s × 14.7 = 9,878 GFLOPS`。AI < 65.6，带宽那条线更低，所以天花板由带宽决定。

### 瓶颈在哪

完成度只有 23%，意味着 naive 连自己那条（本来就很低的）带宽天花板都没摸到——
**它不是带宽瓶颈**。

真正卡住它的是 global load 的延迟和条数：

- 每 FMA 配 2 条 global load，N=4096 下总共 `6.87e10 × 2 = 1.37e11` 条
- 每个 warp 发出 global load 后，要等几百个周期数据才回来
- `sum += ...` 是一条 4096 次长的串行依赖链，下一轮必须等上一轮算完，
  等待期间没有足够多的独立工作可以切过去

所以 naive 慢不是「读得多」，是「发得多、等得久」。

### 下一步

shared memory —— 也就是 tiled 版。把 31/32 的读从 global 换到 shared，
访问延迟从几百个周期降到几十个周期。

---

## 2. tiled —— 先把重复读接进 shared memory

### 结论

耗费了 47.05 ms，总计 2,921 GFLOPS，是 FP32 峰值的 6.6%。AI = 15.2，远低于 ridge point 65.6，
落在 memory-bound 区。

### AI 为什么这么低

每一个 block 读取 A 的 32 行和 B 的 32 列。

### 复用率怎么计算

`32*4096*4 + 4096*32*4 = 1 MB`，block 数量 `4096/32 * (4096/32) = 16384`，
一共 16 GB，`16 GB ÷ 9.07 GB = 1.76` 倍。

### 天花板怎么取

`672 × 15.2 = 10,181 GFLOPS`，完成度 `2,921 ÷ 10,181 = 0.287`。

### 瓶颈在哪

影响性能的仍然不是带宽，而是 load 指令次数——它没变，和 naive 一样都是 2N³ 条，
只是从 global 转移到了 shared。**换的是「读的地方」，不是「读的次数」**，
所以只降低了延迟，没有减少指令条数。

### 下一步

register tiling

---

## 3. reg 4×4 —— 每线程 16 个累加器

### 结论

reg 4×4 版在 N=4096 上跑 10.84 ms，合 12,677 GFLOPS，是 FP32 峰值的 28.7%。
AI = 31.6，低于 ridge point 65.6，仍在 memory-bound 区。
对应带宽天花板 21,229 GFLOPS，实际达到 `12,677 ÷ 21,229 = 60%`。

### AI 为什么涨到 31.6

每线程算 4×4 = 16 个输出，每个 k 只需 8 次 load（4 个 A + 4 个 B）养 16 次 FMA，
load/FMA 从 2.0 降到 0.5。DRAM 流量因此从 9.07 GB 降到 4.35 GB。

### 复用率怎么计算

如果没有 L2，每一个 block 需要 `32*4096*4 + 4096*128*4 = 2.5 MB`，
一共 `4096/128 * (4096/32) = 4096` 个 block，无 L2 时 `4096 * 2.5 MB = 10.24 GB`，
实测 4.35 GB，复用率 `10.24 ÷ 4.35 = 2.35` 倍。

### 天花板怎么取

`672 × 31.6 = 21,229 GFLOPS`。AI < 65.6，带宽那条线更低，所以天花板由带宽决定。

### 瓶颈在哪

带宽利用率 60%、算力利用率 28.7%，两者差一倍，**瓶颈在带宽侧**。
差的 40% 来自 block 内部「填 shared」和「k 循环」两段串行——填的时候算力闲着，
算的时候带宽闲着，只能靠 SM 上并存的 5 个 block 错峰；而各 block 工作量相同、
容易跑成同相位，加上 `__syncthreads()` 把 warp 钉在同一时刻，错峰并不完美。

### 下一步

8×8 —— 每线程 64 个累加器，把 DRAM 流量再压一半（实际压到 1.19 GB）。

---

## 4. reg 8×8 —— 每线程 64 个累加器，唯一越过 ridge 的一版

### 结论

reg 8×8 版在 N=4096 上跑 6.09 ms，合 22,570 GFLOPS，是 FP32 峰值的 51%。
AI = 115.5，高于 ridge point 65.6，因此落在 compute-bound 区，这是四版里唯一越过 ridge 的。

### AI 为什么涨

AI 从 31.6 变成 115.5，即 3.66 倍。由公式 AI = FLOP ÷ 字节，这里 FLOP 并没有改变，
是分母变小了：tile 从 20 KB 涨到 40 KB，L2 的复用率从 2.35 倍提升到 4.3 倍。
DRAM 流量因此从 4.35 GB 降到 1.19 GB。

### 复用率怎么计算

如果没有 L2，对于 8×8，每一个 block 需要 `8*8*4096*4 + 4096*256*4 = 5 MB`，
一共 `16*64 = 1024` 个 block，就是 5.12 GB，实测 1.19 GB，复用率 4.3 倍。

对于 4×4，同理，每一个 block 需要 `32*4096*4 + 4096*128*4 = 2.5 MB`，
一共 `4096/128 * (4096/32) = 4096` 个 block，无 L2 时为 `2.5 MB * 4096 = 10.24 GB`，
实测 4.35 GB，复用率 `10.24 / 4.35 = 2.35` 倍。

### 天花板怎么取

AI > 65.6，所以天花板由算力峰值决定。带宽那条线算出来是 77,616 GFLOPS，
但算力只有 44,100，喂得进去算不出来，取小的。实际达到 22,570，
`22,570 ÷ 44,100 = 51%`。

### 瓶颈在哪

差的部分在于 SM 的指令吞吐：每个 k 迭代一共 80 条指令，只有 64 次 FFMA，
占比 80%。剩下的差距在于 LDS 延迟、循环开销、地址计算。

### 下一步

float4 向量化把 LDS 从 8 次降到 2 次。

---

## 四版合起来看

四个版本在 Roofline 上走了一条完整的路线：

| 版本 | 关键动作 | AI | 完成度 | 墙在哪 |
|---|---|---|---|---|
| naive | — | 14.7 | 23% | global load 延迟 + 条数 |
| tiled | 重复读从 global 换到 shared | 15.2 | 29% | 仍是 global load，只是少了 |
| reg 4×4 | 每线程 16 个输出，load/FMA 降到 0.5 | 31.6 | 60% | shared load 指令 |
| reg 8×8 | 每线程 64 个输出，tile 翻倍 | **115.5** | 51% | SM 指令吞吐（FFMA 只占 80%） |

**四版里前三个都在 memory-bound 区，8×8 把 AI 从 31.6 推到 115.5，一举跨过 ridge。**
但它并没有因此变快更多——天花板从「带宽 × AI」换成了「算力峰值」，
完成度反而从 60% 降到 51%：**换了赛道，墙也跟着换了。**
