顺着走比竖着走快，因为顺着走，一条cache line装有16个int，读第一个会把后面15个都带进来，接下来15次访问都不用碰内存，而竖着走每次跳16KB，落在完全不同的line上，每次搬运64字节只用4字节，剩下60字节全扔。
row-major : 20 ms
col-major : 239 ms
行优先和列优先的对比，差12倍

本机的cache line是64字节，实验设计了按照2^0-2^6跳步一次访问，计算平均时间。
拐点在 s = 16。16 × 4 字节 = 64 字节 = 本机 cache line 大小。

1280KB是本机的L2缓存，256KB能装进去，而且硬件预取器提前把后面的line搬到L1，等不到miss，所以七个步长一样快，4MB超出L2，miss只能落到L3，慢一档，预取器掩盖不了。

组冲突是指：
cache被切成了64个set，每个地址只能用一种规则来选组。
组号=（字节地址/64）%64
b矩阵，同一个方块内j每加1，地址跳N*4

N	跳多少字节	折成 cache line	组号变化
2048	8192	8192 ÷ 64 = 128	128 % 64 = 0 → 永远同一组
2112	8448	8448 ÷ 64 = 132	132 % 64 = 4 → 换组了
每组只有 12 个位置（12 路）。一个方块要挤 16 行进去 → 4 行被不断踢出去又拿回来，这就是组冲突。

N=2112 只是多留了 64 列空位，就让每行落到不同的组 —— 朴素转置立刻快了 2.7 倍（29.802 → 11.023）

B=4时，不出现组冲突的原因是
方块的写入，全落在一个组中，b[j*N+i] N=2048,j+1,2048*4=8192,(8192/64)%64=0,组号没有变化，全在一个组
一个组只有12个位置，B=4<12不冲突，B=16>12有冲突，
冲突的条件是：同一个组里要同时放下的 line 数 > 路的数量
一组12个是来自CPU硬件参数，

容量 = 组数 × 路数 × 行大小。本机 L1 = 64 组 × 12 路 × 64 字节 = 48 KB
