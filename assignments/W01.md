## 第 1 步 · 建文件夹，写三个文件（60 分钟）

### 1.1 建文件夹

在 `C:\Users\Admin\Desktop\GPU\code\` 下面新建一个文件夹，叫：

> 为什么是 02：`00` 和 `01` 是我的环境自检项目。**从 02 开始，都是你自己的。**

### 1.2 写 `math_utils.h`

**需求**（不给你代码，你自己写）：

- 这是一个**头文件**
- 里面**只放声明，不放实现**（函数体不写）
- 声明两个函数：
  - `int add(int a, int b);` —— 返回两数之和
  - `int factorial(int n);` —— 返回 n 的阶乘（n! = 1×2×3×...×n）
- **必须加 include guard**（防重复包含）

**🤔 写完回答这两个问题**（写在 `notes.md` 里）：

1. 头文件里为什么不写函数体，只写声明？
2. include guard 如果不加，什么情况下会出问题？

### 1.3 写 `math_utils.cpp`

**需求**：

- 实现上面两个函数
- `factorial` 用**循环**实现，**不要用递归**
- 文件开头必须 `#include "math_utils.h"`

**🤔 回答**：

3. 为什么 `.cpp` 里要 `#include` 自己的头文件？
   （提示：试试把 `int add(int a, int b)` 故意写成 `int add(int a)`，
   只改实现不改头文件 —— 加上那行 `#include` 会怎样？去掉又会怎样？
   **动手试，别猜。**）
4. `factorial` 用递归写的话，`n = 100` 时会发生什么？为什么？

### 1.4 写 `main.cpp`

**需求**：

- `#include <cstdio>` 和 `#include "math_utils.h"`
- 调用 `add(2, 3)` 和 `factorial(5)`，各打印一行结果
- `main` 返回 0

> ⚠️ 注意 `#include <cstdio>` 用的是尖括号，`#include "math_utils.h"` 用的是引号。
> **顺手查一下这两种写法有什么区别**（这是面试高频题）。

## 第 2 步 · 手动走一遍，看每一站长什么样（90 分钟）

现在开始核心部分。**打开 devshell**：

```bat

```

（这次带了参数，会直接进到你的作业目录。看提示里的 `Current directory` 确认一下。）

### 2.1 预处理 —— 只做"文本替换"

```bat
cl /P main.cpp
```

用记事本打开生成的 `main.i`，**滚到最底下**，找到你写的那几行。

**🤔 回答**：
5. `#include <cstdio>` 那一行去哪了？变成了什么？
6. `main.i` 有多少行？（用 `dir` 看文件大小，或者用记事本看行数）
7. 你只写了 10 来行，为什么结果有几千行？

**这一步的结论**：`#include` 就是**复制粘贴**。就这么简单，也仅此而已。

### 2.2 编译 —— 变成汇编

```bat
cl /FA /c main.cpp
```

打开生成的 `main.asm`，**搜索 `add`**（Ctrl+F）。

**🤔 回答**：
8. 你能在上面找到 `call` 这个指令吗？它 call 的是什么名字？
9. 你写的 `int x = add(2,3);` 变成了几行汇编？大致是什么？

**看不懂没关系**，这周不需要看懂汇编。只要**亲眼确认"我的一行 C++ 变成了十几行汇编"**就够了。

### 2.3 编译 —— 变成目标文件

```bat
cl /c math_utils.cpp
cl /c main.cpp
```

现在目录里应该有 `math_utils.obj` 和 `main.obj`。

用 `dumpbin` 看看里面有什么：

```bat
dumpbin /symbols math_utils.obj
```

**🤔 回答**：
10. 输出里能找到 `add` 和 `factorial` 吗？它们长什么样？（会是一串奇怪的字符，把原文抄下来）
11. 打开 `main.obj` 看：
    ```bat
    dumpbin /symbols main.obj
    ```
    `add` 在里面吗？为什么？

**这一步的结论**：`.obj` 里存的是**机器码 + 一张"符号表"**。
`math_utils.obj` 说"**我提供了** add"，
`main.obj` 说"**我需要** add"。
谁把它们接起来？下一站。

### 2.4 链接 —— 拼成可执行文件

```bat
link main.obj math_utils.obj /OUT:app.exe
app.exe
```

**🎉 看到你打印的数字了吗？** 你刚刚手工完成了整个构建流程。

## 第 4 步 · 静态库与动态库（60 分钟）

同样一份 `math_utils`，可以打包成两种东西。

> ⚠️ **先做一件事：把目录里旧的 `.obj` `.lib` `.exe` 全删掉重来。**
> 记住上一轮的教训 —— `lib` 是**打包**不是**编译**。
> 它只抄当时的 `.obj`，之后再改 `.cpp`，库里还是老的。
>
> ```bat
> del /q *.obj *.lib *.exe *.dll *.exp *.i *.asm
> cl /nologo /EHsc /utf-8 /c main.cpp math_utils.cpp
> ```

### 4.1 静态库（命名成 `statics.lib`，别用原名）

```bat
lib /OUT:statics.lib math_utils.obj
link main.obj statics.lib /OUT:app_static.exe
```

**记录 A**：`dir app_static.exe` 多少字节？
**记录 B**：`dumpbin /dependents app_static.exe` 列出了哪几个 dll？

### 4.2 动态库（命名成 `dyns.dll`，别用原名）

```bat
cl /LD math_utils.cpp /Fe:dyns.dll
```

> 故意用不同的名字，否则它和 4.1 会互相覆盖，你就没法对比了。

**🤔 回答**：
21a. 这条命令的**完整输出**原样贴上来。它有没有说"正在创建 `.lib`"？
21b. `dir dyns.*` —— 实际生成了哪几个文件？
21c. `dumpbin /exports dyns.dll` —— **导出表里有东西吗？**
     `dumpbin /symbols dyns.dll` 里有没有 `?add@@YAHHH@Z`？
     **两个命令的结果对得上吗？**
21d. 猜：为什么 dll 造出来了，却"什么门都不开"？

### 4.3 对比

先把导出表的问题解决，再跑这两条：

```bat
link main.obj dyns.lib /OUT:app_dynamic.exe
dumpbin /dependents app_dynamic.exe
```

**🤔 回答**：
22. 用静态库和用动态库，最终 exe 的大小差多少？**实测，不要猜。**
    如果差不多大，**先别急着下结论** —— 想想 exe 里体积最大的是什么。
23. 如果 `dyns.dll` 被删掉，`app_static.exe` 还能跑吗？`app_dynamic.exe` 还能跑吗？
    **实测。** 跑不起来的那个，`echo %ERRORLEVEL%` 是多少？把它转成十六进制去搜。
24. 用自己的话说：什么时候用静态库，什么时候用动态库？
    （提示：想想 NVIDIA 的驱动、你公司给硬件写的那套 dll，为什么是 dll 不是 lib）

## 常见坑

| 症状 | 原因 | 解决 |
|---|---|---|
| `'cl' 不是内部或外部命令` | 没在 devshell 里，或者没跑 vcvars | 用 `.\devshell.bat` 打开命令行 |
| `.bat` 文件里写中文后报奇怪的错 | cmd 用 GBK 解析 UTF-8 | **`.bat` 文件只写英文** |
| 中文注释在 `main.i` 里乱码 | 编码问题 | 编译时加 `/utf-8` |
| `LNK1104: 无法打开文件 xxx.obj` | 没有先编译 | 先 `cl /c`，再 `link` |
| `LNK2019: 无法解析的外部符号` | 就是本作业的错误 2 | 回去看第 3 步 |
