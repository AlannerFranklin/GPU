## ❌ 问题 1：第 3 题你答错了，而且你没动手试

**你的答案**：「故意写成 `int add(int a)` 会报错找不到函数。」

**我实测的结果**（我拿你的文件跑了）：

```
===== 编译阶段 =====
mismatch.cpp
COMPILE_EXITCODE=0          ← 编译完全通过，一个警告都没有！

===== 链接阶段 =====
main.obj : error LNK2019: 无法解析的外部符号
           "int __cdecl add(int,int)"，该符号在函数 main 中被引用
 已定义且可能匹配的符号提示:
    "int __cdecl add(int)"                                          ← 链接器帮你找到了
mm.exe : fatal error LNK1120: 1 个无法解析的外部符号
```

**报错发生在链接阶段，不是编译阶段。**

### 为什么？这才是第 1 步的全部意义

`int add(int a)` 和 `int add(int a, int b)` 在 C++ 里是**两个不同的函数**（这叫重载）。
编译器看到 `int add(int a) { ... }` 认为你在**合法地定义一个新函数**，根本不觉得有问题。

它**不知道**你本来想写的是 `add(int,int)`。除非你 `#include` 了头文件，
让它能拿声明和实现对照 —— 但即使 `#include` 了，重载规则也让它认为两个都是合法的。

**所以**：

> **编译器只看单个文件，链接器才看全局。**
>
> 声明和实现不一致这种事，编译器**没有能力**发现，
> 因为它编译 `math_utils.cpp` 时根本不知道 `main.cpp` 会怎么调用。

### 你要做的

自己动手复现一遍（别信我的截图）。把 `LNK2019` **一字不差**抄进 `notes/errors.md`。

**🤔 回答**：链接器那句「已定义且可能匹配的符号提示：`int __cdecl add(int)`」
说明了什么？它为什么会知道你可能想写哪个函数？

## 🔄 问题 3：include guard —— 这里有个反转

你说不知道怎么加。**语法自己查**（关键词：`include guard` 或者 `#pragma once`），
这是查手册的事，不算本事。

但**为什么需要**，这个很有意思，而且有个反转：

### 反转：你的头文件现在**不加 include guard 也不会报错**

我实测过 —— 把 `math_utils.h` 包含两次，编译通过。

**因为函数声明可以重复。** C++ 允许你声明同一个函数一百遍，不报错。

## ⚠️ 问题 5：你没想到 factorial 会溢出

`int` 装不下大的阶乘。我实测了：

```
factorial(12) = 479001600      ← 正确

factorial(17) = -288522240     ← 变成负数了
```

**🤔 回答**：

1. `int`（32 位有符号）最大能表示多少？去查一下，或者用 `#include <climits>` 打印 `INT_MAX`。

3. **为什么 17 开始变成负数？**（这题有意思，想想二进制补码。给你个线索：
   溢出后最高位变成 1 了，而有符号数里最高位是符号位）
4. 这就是为什么 `factorial` 应该有个**前置检查**。你会怎么改？
   （不用写代码，用中文描述你的思路）

> 这个问题在 GPU 编程里会变本加厉 —— 你在 GPU 上算的东西，
> 溢出往往是**静默**的，不会报错，只会给你一个看起来很正常但完全错误的数字。
