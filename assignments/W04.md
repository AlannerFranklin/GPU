## 交付物 1 · `MyVector<T>`

### 类里三个成员

| 成员 | 类型 | 含义 |
|---|---|---|
| `data` | `T*` | 指向堆上的元素数组 |
| `size_` | `size_t` | 现在有几个元素 |
| `cap_` | `size_t` | 现在最多能装几个 |

**`size_` 和 `cap_` 是两回事** —— 一个是"装了几个"，一个是"房子有多大"。上周 `std::vector` 那 2137 次搬家，就是这两个数在打架。

### 要写的函数

| 函数 | 干什么 |
|---|---|
| `MyVector()` | 空数组 |
| `~MyVector()` | `delete[] data` |
| `size()` / `capacity()` | 读那两个数 |
| `operator[](i)` | 返回第 i 个元素的**引用** |
| `reserve(n)` | 要够 n 个位子的空间 |
| `push_back(const T& v)` | 放一个**左值**进去 |
| `push_back(T&& v)` | 放一个**右值**进去 |
| 拷贝构造 / 拷贝赋值 | 五法则 |
| 移动构造 / 移动赋值 | 五法则 |

### 硬性要求

**① 扩容时必须用移动搬家，不许拷贝。**

上周你量到：1000 次 `push_back` 里 **2137 次移动全花在搬家上**。这周轮到你自己写 —— **如果你写成拷贝，那 2137 次会变成 2137 次深拷贝**，每个元素重新 `new` 一遍。**两种写法都跑，数字记下来。**

**② `push_back` 必须写两个版本。** 写完跑这个：

```cpp
MyVector<MyString> v;
MyString a("hello");
v.push_back(a);              // 左值 —— 走哪个？
v.push_back("world");        // 临时对象 —— 走哪个？
v.push_back(std::move(a));   // 显式右值 —— 走哪个？
```

**用上周的 `move_ctor_count` / `copy_ctor_count` 验证。**

2. 扩容的完整步骤是什么？（提示：**旧数据不能先 `delete[]` —— 为什么？**）
3. 把扩容里的 `std::move` 去掉，`MyVector<MyString>` 跑 1000 次 `push_back` 会怎样？**跑一遍，贴两组数字。**

## 交付物 2 · `UniquePtr<T>`

**上周那道题的实体化：独占型资源，拷贝构造 `= delete`。**

### 成员

| 成员 | 类型 | 含义 |
|---|---|---|
| `p_` | `T*` | 我独占的那个对象 |

### 要写的函数

| 函数 | 干什么 |
|---|---|
| `UniquePtr(T* p = nullptr)` | 接管一个裸指针 |
| `~UniquePtr()` | `delete p_` |
| `UniquePtr(const UniquePtr&) = delete;` | **拷贝构造：删掉** |
| `operator=(const UniquePtr&) = delete;` | **拷贝赋值：删掉** |
| `UniquePtr(UniquePtr&& o) noexcept` | 偷指针 + 置空 `o` |
| `operator=(UniquePtr&& o) noexcept` | 同上，注意自赋值 |
| `T& operator*()` | 解引用 |
| `T* operator->()` | 成员访问 |
| `T* get()` | 看指针，**不**交出所有权 |
| `T* release()` | **交出所有权**，自己不删 |
| `void reset(T* p = nullptr)` | 换一个，旧的删掉 |

### 硬性要求

**① 拷贝构造和拷贝赋值要显式写 `= delete`** —— 不是"不写"，是**写出来**。这是给编译器和你自己看的注释。

**② 把这两行加进 `main`，把编译错误原文贴进 notes：**

```cpp
UniquePtr<MyString> a(new MyString("hello"));
UniquePtr<MyString> b = a;
```

**③ 把 `UniquePtr<MyString>` 放进 `std::vector`，`push_back` 几个进去。**

### 🤔 回答 5–6

5. `= delete` 和"什么都不写"有什么区别？（提示：什么都不写的话，编译器会替你干什么？）
6. 移动赋值里**还需要自赋值守卫**吗？想想 `a = std::move(a);` 会发生什么。**跑一遍验证。**

## 交付物 3 · `SharedPtr<T>`

选做。**40 分钟内写完交付物 1 的话就做它。**

### 成员

| 成员 | 类型 | 含义 |
|---|---|---|
| `p_` | `T*` | 我指向的那个对象 |
| `count_` | `int*` | **指向堆上的一个计数器** |

### 硬性要求

- **拷贝构造** → `++(*count_)`（大家一起来，谁都不删）
- **析构** → `--(*count_)`，**减到 0 才真的 `delete p_`**
- 拷贝、移动**都能写**（跟 `UniquePtr` 正相反）

### 🤔 回答 7–8

7. **`count_` 为什么是 `int*` 而不是 `int`？**（提示：上周的盒子图 —— 两个对象的 `count_` 格子里，必须装什么？）
8. 析构里为什么先 `--` 再判断 `== 0`？**如果 `SharedPtr` 是从函数里返回的呢？**
