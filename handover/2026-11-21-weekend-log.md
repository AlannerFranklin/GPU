## ✅ 优先级 1：4 种内存序（2026-11-21 完成）

闭卷四项验收全过：

| 验收项 | 结果 | 证据 |
|---|---|---|
| ① 四种语义 | ✅ | relaxed=只保原子不保序；release=封存之前；acquire=解封之后；seq_cst=acquire+release+全局唯一顺序 |
| ② 为什么必须 acquire/release | ✅ | 能指出 push 的 `head.store` / pop 的 `head.load` 具体越权行，并能说出 relaxed 会导致「读到半新半旧」 |
| ③ seq_cst 的代价 | ✅（提示后） | x86 唯一允许的重排是 store→load，所以 seq_cst 的代价全在 store 侧：`xchg`；acquire/release 是零指令 |
| ④ 对应 CUDA | ✅ | `__threadfence()` = release（无配对 load 的 store 侧屏障） |

**教学记录**：讲了 as-if 规则（编译器凭什么敢重排）和 store buffer（CPU 侧重排）。
学员第一次把「release 保证两个线程按顺序执行」说错——已纠正：内存序从不保证线程间顺序，
只保证**单个线程的写何时对别人可见**。

## ✅ 优先级 3：std::move（2026-11-21 完成）

闭卷四项验收全过（载体：`code/04-mystring/mystring.cpp` 自己写的 MyString）：

| 验收项 | 结果 | 备注 |
|---|---|---|
| ① move 本身不移动任何东西 | ✅ | 从"换了个别名"纠正为"static_cast 改值类别"；链式因果：类型转换→重载选择→移动构造里才搬 |
| ② 移动后源对象状态 | ✅ | 从"野指针"纠正为 **nullptr / 有效但未指定**（主动置空，非未定义） |
| ③ 参数为什么是 `MyString&&` | ✅ | 非 const 引用（要掏空源）+ 重载区分器 + 按值会无限递归 |
| ④ 哪一行真正转移所有权 | ✅ | 第 40 行 `o.data = nullptr`——第 38 行只是共享，"置空"才让转移独占生效 |
