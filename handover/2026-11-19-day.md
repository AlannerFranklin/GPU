## 四、第 14 周：histogram

新建 `code/16-histogram/`。

### hist_common.h 的关键设计

**和前面几个 harness 的根本差别：`atomicAdd` 是累加的，而 harness 会 launch 4 次。**

所以 `cudaMemset` 必须**放进 rep 循环、放在 `Record(start)` 之前**：

```cpp
for (int rep = 0; rep < 4; rep++) {
    cudaMemset(out_d, 0, NUM_BINS * sizeof(int));   // 每次都清，且在计时窗口外
    ...
}
```

这正是 11-18 晚 `reduction_v6` 那个 bug 的正式修法。**面试/histogram 场景必须这样写。**

指标用 **GB/s** 不用 GFLOPS——histogram 不做浮点运算。

### 两版

| 版本 | 做法 | 状态 |
|---|---|---|
| `histogram_naive` | 每线程一个元素，直接 global `atomicAdd` | 编译过，待跑 |
| `histogram_shared` | shared 私有直方图 + grid-stride(1024 blocks) + 跳过空 bin | 编译过，待跑 |

**学员犯的错（shared 版）：**

```cpp
for (int i = blockIdx.x*blockDim.x + threadIdx.x; i < N; i += blockDim.x*gridDim.x) {
    if (hist[i] > 0) atomicAdd(&out[i], hist[i]);     // ← 遍历了 N，但 hist/out 只有 256 格
}
```

**他把「遍历输入元素」的循环形状套用到了「遍历 bin」上。** 已讲清：两个循环长得像，
但遍历的对象和范围完全不同（0..N-1 vs 0..NUM_BINS-1），且合并那一步不需要 grid-stride。

### bank_conflict.cu 微基准

两个 kernel 做同样多的 shared 读（1024×256×10000 = 26 亿次），只改地址：

```
conflict_free    t[threadIdx.x]        bank = tx → 0..31，无冲突
conflict_32way   t[threadIdx.x * 32]   bank 恒 = 0 → 32 路冲突
```

**用 `volatile` 阻止编译器把循环里的重复 shared 读提到寄存器**——否则一次 shared 读都不剩。

这是第 14 周「能解释 bank conflict 的代价」的**实测载体**。

## 六、第 15 周：流与异步

新建 `code/17-stream/`。

### 已讲的核心模型

**所有 GPU 调用都是「往流里塞任务」，CPU 不等待。**

```
单流队列：[拷1][算1][拷1'][拷2][算2]...     ← 12 个任务排成一队
多流：    四条队列并行推进                    ← 靠「不同硬件同时工作」
```

**拷贝走 Copy Engine，计算走 SM。** 单流时两者轮流闲着——这就是要重叠的东西。

**pinned 内存（`cudaMallocHost`）是异步的前提**：pageable 内存的物理地址不固定，
驱动必须先同步拷到锁定缓冲，`cudaMemcpyAsync` 会悄悄退化成同步。

**计时窗口包住 12 次操作**：`cudaEventRecord` 本身也是往流里塞的「打时间戳」任务，
所以 start/stop 之间的所有工作都被计入。

### 两版

### 学员当天问倒的两个基础问题（已讲）

**① `h_a + k*CHUNK_N` 为什么不能写 `h_a[k*CHUNK_N]`**

`memcpy` 要地址不要值。核心恒等式：`a[i] ≡ *(a+i)`，所以 `&a[i] ≡ a+i`。
`h_a[k*N]` 是 `float` 值，`h_a + k*N` 是 `float*`。

**② 为什么 `d_a[k]` 是指针而 `h_a[k]` 不是**

**`x[k]` 的类型 = `x` 的元素类型。**

```
float*  h_a       元素是 float   → h_a[k] 是 float
float*  d_a[4]    元素是 float*  → d_a[k] 是 float*
```

学员一度猜「因为四块独立内存不连续所以要单独算」——**混淆了「指针数组」和「连续内存」**。
已讲清：`d_a[k]` 只关心「数组第 k 格里装了什么」，和那四块显存连不连续无关。

（这一条对应 `progress.md` 第 2 周的 `int *p[5]` 内存图，学员在真实代码里撞上了，可以打勾。）
