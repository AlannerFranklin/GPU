  说"我还是得想清楚下标是怎么计算的"，要求先把这一层夯死再写 kernel。
  **这个判断是对的，不是拖延**——他前面积累的下标错误（见文末"学员状态"）说明这是欠账。

按讲解顺序：

1. **矩阵 → 一维数组**：行优先；`下标 = 行 × 行宽 + 列`
   反解：`行 = 下标 / 行宽`、`列 = 下标 % 行宽`
2. **行数 ≠ 行宽**（今天最大的一个坑）
   - 行宽 = 列数 = 横着数出来的那个数
   - **行数在 `行 × ? + 列` 里根本不出现**，只在算 grid 和判边界时用
3. **`threadIdx` 只在 block 内部唯一**
   - 四个 block 里各有一套一模一样的 `threadIdx`
   - 全局唯一 = `blockIdx * blockDim + threadIdx`
   - **warp 线性化（`threadIdx.y * blockDim.x + threadIdx.x`）只在 block 内成立，
     warp 绝不跨 block** —— 因为 block 整体被调度到一个 SM
4. **二维坐标映射**：`.x` 管列（水平）、`.y` 管行（竖直）
   - 除了几何对应，还有性能理由：`.x` 变化最快，必须给列号，
     否则相邻线程地址差一整个行宽 → 退化成 `vector_add_strided` 那种散开访问
5. **谁乘 N，谁就是行**（今天最有用的一条判据）

   | 写法 | 乘 N 的是 | 行固定还是列固定 |
   |---|---|---|
   | `A[row * N + k]` | `row` | 行固定 → **横着扫一行** |
   | `B[k * N + col]` | `k` | 列固定 → **竖着扫一列** |
   | `C[row * N + col]` | `row` | 写回位置 |
   | `out[col * N + row]` | `col` | **这就是转置** |

6. **`idx = row * N + col` 与 `col * N + row` 的区别就是转置**
   —— 他自己在 `transpose.cu` 里写过，但今天才把这两行和"谁乘 N"接上
7. **对拍方法论**：主机端用三重循环独立重算，和 GPU 结果比
   - 主机端**只有一个执行流**，不存在"我是几号线程"，所以 `r`/`c` 是**直接点名**的，
     不是用 `blockIdx`/`threadIdx` 算出来的
   - 这是今天学员卡住的最后一道坎（第 105 行 `r = ;` 空着不会填）

| 轮次 | 题目 | 结果 | 具体错法 |

### 结论

- **稳定了**：`cudaMalloc` 的 `_d`（今天零失误）、缓冲区大小、计时窗口、
  `min_time = std::min(...)`、D2H 目标必须是设备上被写过的那块
- **同一个错误的统称：算术跳步**
  凡是题目里躺着一个现成的数字，他就直接抓来当答案，跳过乘法/加法那一步。
  **处方已经给了：「先写算式，再写答案」，不许直接报数字。**
  今晚跑 matmul 时如果他又犯，重复这条处方即可，不用重讲原理。
- **填表**（把 `blockIdx.x` / `blockDim.x` / `threadIdx.x` 逐个列出来再代入）
  是唯一验证有效的纠错手段，后面讲索引继续用这个形式
