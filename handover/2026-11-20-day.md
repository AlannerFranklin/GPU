## 一、复盘：`s > 32` 这个边界，第二次栽在同一个地方

**关键事实**：exam 的失败签名和 11-18 晚 v3 修复前**逐位相同**（sum=3.0、rel_err=1.60）。

> **修过的 bug 留在了记忆里，但「为什么那样修」没有。**

### 处理方式：不给答案，让他推

问了两个问题：

1. `s = 128` 那一轮之后，tile[0..127] 各装了几个元素的和？`s = 64` 之后呢？循环什么时候停？
2. 循环结束后有效的是 `tile[0..63]`，但 shuffle 那段只读 `tile[0..31]`——**`tile[32..63]` 谁去收？**

**他第一反应答「改成 `s > 64`」**（跳过更多轮，更糟）。让他把三轮列成表数了一遍之后才纠正。

### 最终给的规则（不是背 `>=`）

> **树的循环必须把「有效范围」缩到「收尾步骤能处理的范围」为止。**
>
> ```
> 初始有效范围    = blockDim.x = 256
> 收尾能处理的    = 32（一个 warp）
> → 循环必须把 256 缩到 32 → s = 32 那一轮必须执行 → s >= 32
> ```

换 blockDim 也能推：512 线程就是 `s = 256,128,64,32`，条件仍是 `s >= 32`。

`reduction_exam.cu` 已改成 `s >= 32`，编译通过，**今晚验证**。

## 二、发现一个异常：PCIe 带宽只有理论值的 18%

从 `scale_v0` 的数据反推：

```
总搬运量 = 128 MB（4 块 × (16 MB H2D + 16 MB D2H)）
min_ms   = 21.18
实测带宽 = 0.125 GB ÷ 0.02118 s = 5.90 GB/s
```

**PCIe 4.0 ×16 理论 32 GB/s，实测通常 20-24 GB/s。5.90 只有 18%。**

工程师确认卡确实插在 4.0 ×16 上，所以不是插错了槽。

**这个发现改变了第 15 周的解释框架**：多流 0.99x 可能不只是「只有一个拷贝引擎」，
还叠加了「搬得本来就慢」。

### 新增 `pcie_bench.cu`

四个大小（1/4/16/64 MB）× 两个方向，纯拷贝不夹 kernel。

**关键实现点**：`cudaEventSynchronize(stop)` 不能少——这里没有任何后续操作会等拷贝完成，
不等的话测到的是「提交花了多久」而不是「拷贝花了多久」。

**今晚的四个数字会分叉出两条路：**

- 64 MB 接近 20 GB/s → 5.9 是因为 16 MB 太小摊不平固定开销 → CUDA Graph 有价值
- 64 MB 也只有 6 左右 → 平台/驱动限制（Windows WDDM 是头号嫌疑）→ 换方向

## 三、CUDA Graph：概念 + 微基准

### 讲到的核心

```
问题：每次 launch 有几微秒的 CPU 开销（校验、打包、入队、通知）
      10000 个小 kernel → kernel 本身 10 ms，launch 开销 50 ms

解法：捕获（记录，不执行）→ 实例化 → 一次提交
省：CPU 提交开销、kernel 间隙
不省：kernel 执行时间、依赖顺序
```

**三个坑（写代码前先讲）：**

1. **`cudaStreamBeginCapture` 不能用默认流**，必须自建流
2. **捕获期间 kernel 不执行**，只是被记录——这是最反直觉的一点
3. **捕获前要 `cudaStreamSynchronize`**，否则上一批未完成的 launch 会被一起捕进去

### 对他当前实验的判断（已讲）

```
stream 实验：12 次操作 / 21.18 ms
launch 开销：12 × 5 µs = 0.06 ms = 0.3%
→ Graph 最多省 0.3%，药不对症
```

**已强调：优化必须对着瓶颈。** 他的瓶颈是「搬得慢」，Graph 治的是「提交得勤」。

### 新增 `graph_bench.cu`

10000 次 `tiny`（单线程加一），对比「N 次 launch」vs「1 次 graph launch」。
kernel 只有几十纳秒，这样 launch 开销才会显形。

**如果加速比只有 1.2 倍**，说明 NVIDIA 近年的 launch 优化已吃掉大部分收益——
那也是有效结论。

## 四、学员当天的基础问题（已讲）

**「`h_a + k*CHUNK_N` 为什么不能写 `h_a[k*CHUNK_N]`」**

memcpy 要地址不要值。核心恒等式 `a[i] ≡ *(a+i)`，所以 `&a[i] ≡ a+i`。
`h_a[k*N]` 是 `float` 值，`h_a + k*N` 是 `float*`。

**「为什么 `d_a[k]` 是指针而 `h_a[k]` 不是」**

学员先猜「因为四块独立内存不连续所以要单独算」——**混淆了「指针数组」和「连续内存」**。

正确规则：**`x[k]` 的类型 = `x` 的元素类型。**

```
float*  h_a       元素是 float   → h_a[k] 是值
float*  d_a[4]    元素是 float*  → d_a[k] 是指针
```

（这一条对应 `progress.md` 第 2 周的 `int *p[5]` 内存图，可以在真实代码里打勾了。）
