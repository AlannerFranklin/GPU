## 一、坐标映射专题：通关

昨天卡死的「三层坐标」，今天用 N=256 / block(32,8) / grid(2,8) 的小例子重讲，**全部通了**：

| 练习 | 结果 |
|---|---|
| block(1,5) 覆盖哪 32 行 128 列 | ✅ |
| 反推 C[200][30] 落在 block(0,6) | ✅ |
| 正推 ty=2,tx=7 的 4 行 4 列（168–171 / 135,167,199,231） | ✅ |
| 反推 C[175][210] → ty=3,tx=18,i=3,j=2 | ⚠️ 第一次把 tx/j 掉反（算出 j=18 越界没自查） |

**掉反的原因**：把「行方向商给线程」的惯性套到了列上。行的公式是 `i + ty×4`（连续的是 i），
列是 `tx + j×32`（连续的是 tx），**取余的对象不一样**。

**给的统一规则（已证明有效）**：

> 块内号 = 连续的那个 + 另一个 × 连续那个的总数
> 行：`块内行号 = i + ty×4`　列：`块内列号 = tx + j×32`
> 反推取余：`i = 行号 % 4`、`tx = 列号 % 32` —— **余数永远给「连续的那个」**
> 行和列故意不对称：行是嵌套切分（32→4→1），列是交织切分（128→1→32），
> 后者是为了让一个 warp 的 32 个线程铺满 32 个 bank。

**自查习惯已教**：`i`、`j` 只能是 0..3，算出别的数就是错了。

### 最终内核（正确性已人工核对）

```cpp
__global__ void matmul_reg(float* A, float* B, float* C, int N) {
    __shared__ float As[32][32];
    __shared__ float Bs[32][128];

    int block_row  = blockIdx.y * 32;
    int block_col  = blockIdx.x * 128;
    int thread_row = threadIdx.y * 4;

    float acc[4][4] = {0};
    float a[4];
    float b[4];

    for (int t = 0; t < N / 32; t++) {
        for (int i = 0; i < 4; i++)
            As[thread_row + i][threadIdx.x] =
                A[(block_row + thread_row + i) * N + t * 32 + threadIdx.x];

        for (int i = 0; i < 4; i++)
            for (int j = 0; j < 4; j++)
                Bs[thread_row + i][threadIdx.x + j * 32] =
                    B[(t * 32 + thread_row + i) * N + block_col + threadIdx.x + j * 32];

        __syncthreads();

        for (int k = 0; k < 32; k++) {
            for (int i = 0; i < 4; i++) a[i] = As[thread_row + i][k];
            for (int j = 0; j < 4; j++) b[j] = Bs[k][threadIdx.x + j * 32];
            for (int i = 0; i < 4; i++)
                for (int j = 0; j < 4; j++)
                    acc[i][j] += a[i] * b[j];
        }
        __syncthreads();
    }

    for (int i = 0; i < 4; i++)
        for (int j = 0; j < 4; j++)
            C[(block_row + thread_row + i) * N + block_col + threadIdx.x + j * 32] = acc[i][j];
}
```

`main()` 沿用 matmul_tile.cu：`block(32, 8)`、`grid(N/128, N/32)`，
1 次预热 + 3 次计时取 min，末尾 3 点对拍。

**正确性推导已逐项核对**：As/Bs 覆盖关系、t×k 联合覆盖 global k = 0…N-1、
写回下标与填 shared 一致，均无误。

## 三、学员今天犯的错（明天/晚上可回访）

分两轮，**第一轮几乎全错，第二轮全对**：

**第一轮（骨架）**
1. `Bs[32][32]` —— 应为 `[32][128]`
2. 两段填充循环根本没写，只留了两个 `__syncthreads()` 挨在一起
3. `main()` 里还是 `block(32,32)` / `grid(N/32,N/32)` 没改
4. sync 位置错了（填充必须在第一个 sync 之前）

**第二轮（内层循环 + 写回）**
1. `a[i] = As[i][k]` —— 漏了 `thread_row`
2. `b[i] = Bs[k][j]` —— ① `b[i]` 的 `i` 不在作用域（编译不过）② 列漏了 `threadIdx.x + j*32`
3. `C[block_row + thread_row + i + block_col + ...]` —— **漏了 `* N`**，行号列号变成了纯加法
4. 写回 C 放在了 `t` 循环**里面**（会写 N/32 次中间结果）

**共性诊断（已当面讲过）**：

> 填 shared、读 shared、写回 C —— **三处下标必须是同一套**。
> 他填 shared 那两行一次写对了，后面两次都掉了东西。

**已提醒**：`row-major` 下标是 `行*N + 列`，行号那一段要加括号。
