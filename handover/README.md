# 交接文档约定（白天 AI ↔ 晚上 AI）

> 两台机器、两个 AI 协作，代码通过 git 同步。**交接文档是两边之间唯一的沟通渠道**，
> 所以每边写的文档，标准是：**对方不看聊天记录、不猜，拿起来就能干活。**
>
> 本文件是两边共同的规则。开工前先读本文件，再读最近一份对方的交接文档。

---

## 1. 分工与机器

| | 白天（公司） | 晚上（家） |
|---|---|---|
| 谁负责 | 公司电脑上的 AI | 本仓库上的 AI（这台） |
| GPU | **无**（不能运行 CUDA） | RTX 4070 Ti Super（sm_89, 16GB） |
| CUDA Toolkit | 13.4（只能做编译检查） | **12.6**（真正执行） |
| 编译器 | VS 2026（MSVC 14.51，`_MSC_VER` 1951） | VS 2022 Build Tools（E:\BuildTools，MSVC 14.44，`_MSC_VER` 1944） |
| 职责 | 学习、写代码、写 day.md | 编译、运行、测性能、写 night.md |

> ⚠️ 家里还装着 VS 2026（D:\cuda），但 nvcc 12.6 不支持它的 MSVC（报 unsupported compiler），
> **禁止用于 CUDA 编译**。build.bat 已自动优先选 E:\BuildTools，无需手动干预。

## 2. 版本铁律（最重要的一条）

**所有源码的编译标准以家里 CUDA 12.6 为底线：**

1. 代码必须能用 **nvcc 12.6** 编译 —— 公司 13.4 只是语法检查，真正执行的是家里 12.6
2. 目标架构固定 **`-arch=sm_89`**（4070 Ti Super = Ada，CC 8.9）
3. C++ 标准统一 **C++17**
4. **禁止使用 CUDA 13.x 专有 API**（家里 12.6 编不过）

> 为什么：12.6 写的代码在 13.4 上能编，反过来不行。且 13.x 的新特性
> 大部分只对 Blackwell（sm_100+）有用，家里的 Ada 用不上 —— 锁定 12.6 零损失。
>
> `code/10-cuda/CMakeLists.txt` 已把这套标准钉死，**新练习复制它，只改 project 名和源文件**。

## 3. 交接文件命名

每天两份，放 `handover/` 目录：

| 文件 | 谁写 | 什么时候写 |
|---|---|---|
| `handover/YYYY-MM-DD-day.md` | 白天 AI | 下班前 |
| `handover/YYYY-MM-DD-night.md` | 晚上 AI | 当晚跑完代码后 |

**每份交接文件标题下必须带「记录时间」行**（精确到分钟，本地时间），
格式：`> 记录时间：YYYY-MM-DD HH:MM`。历史文件只有日期没时间，从 2026-11-07 起执行。

**开工第一件事**：白天 AI 读最新 night.md；晚上 AI 读当天 day.md。
双方都提交 git，靠 git 同步。**绝不靠口头/聊天记录传递信息。**

## 4. day.md 模板（白天 → 晚上）

白天 AI 按此模板写，**运行清单一项一条，写清楚命令和预期**：

````markdown
# 交接：白天 → 晚上 · YYYY-MM-DD

> 记录时间：YYYY-MM-DD HH:MM

## 今天学了什么
- 对应 ROADMAP 第 __ 周；核心概念 / 教材章节：__

## 今天写了哪些代码
| 文件 | 说明 | 自评状态 |
|---|---|---|
| code/__/__.cu | | 能编过 / 没编过 / 不确定 |

## 今晚要跑什么（运行清单）
- [ ] 项目 `__`：命令 `build.bat __ run`，预期输出：__
- [ ] 需要记录的数字：__（耗时 / 带宽 / GFLOPs，铁律二）

## 遗留问题（需要晚上确认的）
1.

## 本日用到的 CUDA / 编译器特性（检查 12.6 兼容）
- 无 / 列出：__
````

**判断写没写清楚的标准**：晚上 AI 能否不查代码、不看聊天记录，直接照着跑。

## 6. 其他约定

- **性能数字是简历**（铁律二）：每个 kernel 必须有耗时，晚上测、晚上记在 night.md 里
- 白天若改了公共文件（build.bat、CMakeLists、README 等），必须在 day.md 里写明
- 白天代码晚上编不过/跑挂了：修复过程完整写进 night.md，白天第二天开工先读它
- 交接文档自己也要 commit 进 git，两边才有得读
- **固定议程：2026 年 12 月最后一周做「门 A / 门 B 分叉决策」**（M4 决策点提前到年底，
  见 ROADMAP「2027 年 7 月求职版调整」）。当天 day.md 增加「## 分叉决策」一节，
  记录学员的选择 + 一句理由，并同步写入 progress.md 的对应行
